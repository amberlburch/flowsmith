# webflow-build  -  the pipeline

## Better Design route

Load `better-design-adapter` during design direction, design-system, motion and visual-review phases. Use it only after discovery and approved brand authority are fixed. Better Design is not a source for client facts, copy, production state or publish approval.

Run `/flowsmith-loop brief` first (preloaded in a flowsmith dispatch): it pulls the `LEDGER-INDEX` entries that match the phase, never the whole ledger, and its BUILD PLAN is the PlanArtifact (a site is always > 8 calls). `~/.claude/agents/flowsmith/dod.md` is the standard every phase is judged against. Every phase writes its completion to the checkpoint manifest and verifies the PUBLISHED output before advancing.

## Checkpoint manifest (session-cap insurance)
`~/.claude/state/flowsmith/<project>/manifest.json`  -  phases completed, site_id, created page/style/variable/collection/component ids, asset map (`{id, hostedUrl, local}`: the original URL and the downloaded original's path), **design_inventory: the path to `<pack>/design-inventory.json`, the design-side denominator (every section the design contains, per page, desktop AND mobile: the one field recording what SHOULD exist rather than what was created)**, current phase's partial state. Written at every phase boundary and before any destructive edit. Snapshots live outside it: before the first `remove_element` or `remove_style` on a page, save its tree to `~/.claude/state/snapshots/<job_id>/<page_id>.json` and each removed style to `styles.json` beside it (flowsmith SYSTEM.md, Isolation and rollback). The gate hook denies both removals without them and ignores the manifest folder's `snapshots/`. Any session can resume from it cold, and `resume-diff` reconciles design-to-site, not merely manifest-to-site.

## Phases

**0  -  Bootstrap (operator moments 1-2).** Human creates/clones the site and hands over site_id. Agent stages and confirms: GSAP hosting toggle ON, staging domain live, **Webflow-subdomain indexing DISABLED**, favicon + webclip uploaded, plan-tier probe (branching? Analyze? single-page publish?), baseline publish, site-resident rules read (`data_agent_instructions_tool`), and every custom domain attached to the site recorded from `get_site` (L-109).

**1  -  Discovery.** Fill `references/discovery.md` from the brief/client materials (WebFetch competitors; migrations: crawl the old site → URL inventory + priorities → evidence-based redirect map). Output includes the keyword/intent/inlink map and the recorded design input (Figma URL | reference set). **Figma-input: `design-inventory.json` (figma-translation intake step 1, in the format webflow-verify's runner reads) is a Phase 1 output alongside the IA artifact and rides through moment 3 with the sitemap: the same approval that gives page-completeness its teeth gives section-completeness a denominator.** Record its path on the discovery phase: `python3 ~/.claude/lib/flowsmith_manifest.py update <project> --phase 1 --status <partial|done> --set design_inventory='"<pack>/design-inventory.json"'`. → IA/sitemap built as an artifact → **operator approval (moment 3)** → pages created via `data_pages_tool` (all `draft: true`).

**2  -  Design direction + system** via `/webflow-design-system`. Path B ends in **moment 3b approval**. System install: variables, naming grammar, style-guide page.

**3  -  Copy.** `/brand-profile` → `/page-copy` (written against the keyword/intent map) → `/humanise` → **operator approval (moment 4)**. Copy is final BEFORE section builds  -  whtml bakes text in; never build twice. The approved copy map lives in the project pack as `copy-map.md` (or `.json`): the runner diffs every page against it (`--copy`). Australian English, no em-dashes.

**4  -  Assets.** Source from client library or generate (`/higgsfield-generate` family: batches ≥ $25 are a T3 approval gate). Descriptive hyphenated filenames BEFORE upload. Upload via `asset_tool.upload_image_by_url` in batches of 2-4 and record managed asset ids in the manifest. **Before `data_assets_tool.compress_assets` (webp/avif):** download each original to `~/.claude/state/snapshots/<job_id>/assets/` (`curl -sfo <file> "<hostedUrl>"`, then check the file size is non-zero) and record it: `flowsmith_manifest.py add <project> --kind assets --items '[{"id":"<asset id>","hostedUrl":"<url before compression>","local":"<local file>"}]'`. Compression replaces the hosted file with no undo, and its new URL breaks every CSS `url()` pointing at the old name until re-pointed (L-99). Weight-budget every page against the 3MB gate now, not at verify.

**5  -  Section builds.** As a dispatched agent (the normal case, SYSTEM.md Working alone) FLOWSMITH builds one `section_[id]` namespace at a time, using the section ids the design inventory assigned; up to 3 parallel section builders only when the dispatcher runs that fan-out itself, never two writers on one site's freeform code (L-83). Each builder owns its `section_[id]` namespace (naming.md is law). whtml_builder for all text-bearing trees; components (`data_component_tool`) for anything used twice; CMS collections editor-safe (`cms-best-practices`, population patterns in `references/cms-population.md`).
- **Element ids, cheaply:** one `data_element_tool` `get_all_elements` per page per wave, its result saved to `~/.claude/_scratch/YYYY-MM-<job_id>/tree-<page_id>.json` (copy the file the harness saves when the result is large) and searched there (grep or a short python), refreshed only after a structural write (whtml insert, `remove_element`, `move_element`). Any lookup still needed goes into ONE `query_elements` call carrying several labelled `queries`, never one query per call. Every read spends the same 60 a minute budget the wave publish needs, and `query_elements` fans out to `/v2/assets` and `/v2/pages`, which 429 under bursts (learned rule 11).
- **Publish mutex:** section builders in a dispatcher fan-out never publish; they report ready. A dispatched flowsmith runs the ONE staging publish per wave itself (`publish_site` is ~1/min, learned rule 20), through webflow-verify's loop: publish lock under the job's id, `publishToWebflowSubdomain: true` with `customDomains: []`, a runner check since the previous publish, and the polled wait for the new `Last Published` stamp. The gate hook denies a publish missing any of these. Each section is verified from that single publish.
- **Per-section grounded check (mid-build, not end-gate):** after the wave publish, run the runner with `--inventory` on the wave's pages, so every **design-inventory row** for those pages is checked, not each finished section: **a row with no built `section_[id]` is a build defect, not a scope decision** (iterating built sections passes every section you built while whole designed sections silently never exist). Then `/webflow-verify mode: section` on each: ΔE + VLM judge against its reference slice (its section-library contract is the pass target), BEFORE the next phase. Section mode reads from the single wave publish and NEVER publishes on its own; `element_snapshot_tool` is a best-effort faster path when the Designer bridge is live (flaky). A bad section otherwise propagates through later builds before the end-gate; catching it at phase N is far cheaper.

**6  -  Motion pass** via `/webflow-motion`. Signature moment first, then section moments (counted  -  3-5 max each). Each recipe's contract asserted.

**7  -  SEO/AEO module.** Meta contract per page (`data_pages_tool`  -  patterns, lengths, SERP previews emitted); per-page OG images; schema map implemented (runtime-injection where the templated-{{wf}} trap applies); paginated lists self-canonicalise; internal links per the inlink map; sitemap flags (`data_sitemap_tool`); Search Console meta injected. Custom 404 page built.

**8  -  a11y pass.** Keyboard nav, focus visibility, marquee pause, ARIA on Finsweet components, reduced-motion  -  the runner's `a11y` and `state` checks, then `webflow-skills:accessibility-audit` for both themes.

**9  -  Verify loop** via `/webflow-verify` (phase mode, all pages). Pages flip from draft only on entering their own loop; unlinked from nav until green. Max 3 rounds per page then escalate.

**10  -  Revision rounds (2 in scope).** Intake: `data_comments_tool` + `webflow-skills:review-comments`, or operator-pasted feedback (moment 6). Classify each item: in-scope fix / scope change (flag, don't absorb) / defer. Fix → verify → resolve comments → round closed.

**11  -  Launch.** Staging handover → operator does the site-settings SEO pass (moment 6b: redirects, robots.txt, global canonical, Search Console verify  -  values staged) → **T3 production publish (moment 7, approval card; after the operator's yes the main session writes the grant `~/.claude/state/approvals/webflow-production-<site_id>.json`, without which the gate hook denies it; the publish runs under the publish lock taken under the job's id, like a staging one)** → **exit condition: `/webflow-verify` launch mode green on the custom domain** (200s, no noindex, robots sane, sitemap + canonicals on custom host, favicon, redirect spot-curls).

**12  -  Post-launch.** **Schedule the 30-day smoke for real**  -  `mcp__scheduled-tasks__create_scheduled_task`, weekly ×4 (the runner with `--noindex forbid --sitemap` on the custom domain, a Lighthouse CLI re-run, and a form-submission check via `data_forms_tool`), and record the returned task id in the manifest (`add --kind schedule`) as the closure evidence  -  never in `custom_code` (it would corrupt the two-surface footprint count); "scheduled" without a task id is not done (the session ends at handover, so nothing else will run it). Handover doc (structure per naming.md, where motion code lives, CMS editing guide, operator runbook). **Per-project cost report** via `flowsmith_manifest.py report <project>` (operator minutes + run-record cost) folded into the handover  -  not `/insights`, which aggregates by skill not project. DoD walked line-by-line  -  green, or waived-with-reason in the honesty ledger.

## Resume protocol (cold session)
1. Read the manifest (`lib/flowsmith_manifest.py read`)  -  never guess field names, the schema lives in the helper.
2. Validate the site is live: `get_site` on the manifest's site_id.
3. Curl the staging URL  -  published ground truth beats manifest claims.
4. Reconcile: `flowsmith_manifest.py resume-diff` probes live pages/styles/variables/scripts vs the manifest; anything the manifest claims but the site lacks (or vice versa) is listed before work resumes.
5. Continue at the first phase whose outputs did NOT verify against the published site  -  not the first phase the manifest merely marks complete.

## Budget & audit discipline
- **Tool-call ceiling (hook-enforced, the real guardrail):** the gate hook warns a flowsmith dispatch at 150 tool calls and caps it at 200, after which it allows only state-saving calls (the set is in SYSTEM.md Working alone), and 40 calls past it only the report. Size waves at about 150 calls (SYSTEM.md Working alone) so each wave's publish, verify and handoff land under the cap. Per-phase `flowsmith_manifest.py budget --max-calls` and `spend` still count calls for the project report; `spend` exits non-zero on breach: STOP and escalate like the 3-fix-round rule. `--cost-ceiling` stays best-effort (self-reported dollars are approximate).
- Long builds: condense stale history on a concrete trigger  -  when either (a) a phase >2 boundaries back is still in raw context, or (b) context passes a ~50% token watermark. Condensation = replace those phases' raw episodic with their manifest summary entries (the manifest is the durable record; per-turn cost stays bounded, which is what makes cold-resume cheap).
- Log a 15-25 word audit-context line per mutating batch (`log --phase N --context "..."`) so post-mortems read what each write INTENDED.

## Standing rules
- A phase is complete when its published output verifies, not when its API calls succeed.
- Freeze publishes while a staging URL is client-shared except the page under review.
- Escalations carry evidence: expected vs published, attempts made, operator action needed.

## Eval Criteria
Layer (a): given a fixture brief, the emitted plan MUST sequence copy before section builds, flip build order gates correctly (IA approval before design, design approval only on references path), include Phase 0's noindex+GSAP+favicon checklist, mark asset-gen ≥$25 and production publish as gated, batch one staging publish per wave under the publish lock with `customDomains: []` (no per-section publish), keep originals before any asset compression, and end launch with the production SEO re-run; MUST NOT absorb scope changes in revisions or leave pages published mid-build.
Layer (b): pipeline run on the eval fixture site pinned in `agents/flowsmith/eval/fixture.json` (its rules bind, and nothing runs while its `site_id` is null) reaches phase 9 with a green verify and a complete manifest that a cold session can resume from.
